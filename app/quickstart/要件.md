# 要件定義書：tsuzuri のクイックスタート

## 1. 依頼

「配布するとき　一番最初にＲＥＡＤＭＥかクイックスタートあたりでtsuzuriのデータ同梱して　最初はそれが開くようにしとかない？」（2026-11-18）。続けて、README ではなくアプリのクイックスタートとして書く、と選んだ。
同じ日にレビューの段階（接続の確認・衛星の要否・初めて出る語の主題・型8）が増え、要件定義書と設計書にもコメントを残せるようになった（ADR-0005）。この版は、それに合わせて書き直す。

## 2. 書く理由

tsuzuri を入れて初めてアプリを開くと、文章一覧は空で、読める文章が1つも無い。左右のアイコン・文詳細・コメントが何のためにあるかを説明する文書も無い。
この文章が最初に開くことで、読み手は tsuzuri で書かれた文章そのものを使い、文を選び、コメントを残しながら画面の読み方を覚えられる。読み手が説明を読むだけで終わらず、手を動かして確かめられるようになる。

## 3. 公開する場所と読み手

tsuzuri の配布物に同梱し、アプリを初めて開いたときに最初に開く。
読み手は、tsuzuri のスキルとアプリを入れて、アプリを初めて開いた人である。Claude Code で日本語の文章を書かせている人で、説明文を書かせる人も小説を書かせる人もいる。AI に文章を書かせ慣れた人から、文章を仕事で直している人まで幅がある。
読み手は、tsuzuri の言葉（執筆意図・文機能）をまだ知らない。読み手は、このアプリの画面を開いた状態で、この文章を読む。
読み手は、この項目から、自分が置かれた場面（アプリを開いたばかりで、手元に画面がある）に合わせた説明を受け取る。

## 4. 範囲と範囲外

扱うこと：
- tsuzuri が何を書かせるか（一文ごとの執筆意図と文機能）と、それが読み手に何をさせるか
- 本文の読み方（左のアイコンは文章構造、右のアイコンはコメント）
- 文を選ぶと開く文詳細で、執筆意図と文機能を読むこと
- 気になった文や文機能にコメントを残すこと
- Claude Code に tsuzuri で書いてもらう頼み方と、コメントを読んで直してもらう頼み方
- 要件定義書と設計書を開いて読み、項目や段落にコメントを残すこと
- 文章一覧で前に書いた文章を開くこと

範囲外（読み手が期待しそうだが扱わないこと）：
- スキルとアプリの入れ方（README で扱う）
- 記録フォルダの中のファイルの形
- 文機能の語彙の全部の定義（画面で役割にマウスを乗せると出る）
- キー操作の全部（画面の「キーの案内」で見られる）
- 要件定義書と設計書の書き方の決まり（スキルが自分で読む）

読み手は、この項目から、この文章で何を覚えられて、何を別の場所で調べればよいかを受け取る。

## 5. 制約

- 書く事実は、アプリの設計書（app/DESIGN.md）・画面の名前の一覧（app/naming/feature-map.tsv）・スキル（skills/tsuzuri/SKILL.md）にある機能だけにする
- 画面の名前は app/naming/feature-map.tsv のとおりにする（アイコンバー・サイドバー・本文・詳細パネル・文詳細・コメント一覧・要件定義書・設計書・文章一覧・キーの案内・執筆意図・文機能・文章構造・コメント・変更箇所・ハイライト・フィルター）
- です・ます調で書く（配布するスキルの文書と同じ）
- この文章はアプリで読まれるので、本文の中で「この文を選ぶと」のように、読み手の手元の画面を指してよい
- 長さは20〜25文ほどにする。読み手が画面を触りながら、一度に読み切れる量にする
- 書く作業の事情（どの道具で書いたか・何を確かめられなかったか）は本文に書かない

読み手は、この項目から、書いてある操作がどれもアプリに実在することと、画面と同じ名前で書かれていることを受け取る。

## 6. 読んだあと

読み手は、次のことができるようになる。
- 本文の文を選び、文詳細で執筆意図と文機能を読む
- 執筆意図とずれた文や、違うと思った文機能に、コメントを残す
- Claude Code に「tsuzuri で書いて」と頼み、書き終わった文章をこのアプリで開く
- 要件定義書と設計書を開き、違うと思った項目や段落にコメントを残す
- コメントを残したあと「tsuzuri のコメントを読んで直して」と頼み、変わった所を確認する

## 7. 書き手の立場

私（MaryCache・tsuzuri を作った本人）の名前で、配布物の一部として出す。読み手は tsuzuri の使い手である。
tsuzuri を作った理由は、私の言葉では「私の手から離れれば離れるほど良いものにならない」「思考の共有によってAI生成物をたぐりよせる」（docs/requirements.md の BR-02）。本文に私の経験談は書かない。

読み手は、この項目から、tsuzuri がなぜ一文ごとに執筆意図を先に書かせるのかの理由を受け取る。

## 8. 言いたいこと

tsuzuri は AI に一文ごとに執筆意図を先に書かせるので、文を選んでその執筆意図を読み、ずれた所にコメントで返すと、AI の文章を自分の意図へたぐりよせられる。

## 9. 文章の形

説明文。アプリで開く Markdown の文書で、20〜25文ほど。読み手が場所を見失わないよう、操作のまとまりごとに見出しを置く。
