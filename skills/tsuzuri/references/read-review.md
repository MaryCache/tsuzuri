# 3. 人の文を読む

このファイルは、`SKILL.md` の「最初に守ること」と「前提と記録の置き場」を前提に、人やほかの AI が執筆した文章に文機能と推測した執筆意図を付与してレビューする手順と、記録の共有方法をまとめたものです。
`<このスキルのフォルダ>` の読み替え方と共通の決まりは `SKILL.md` と同じです。

人の文を読むときは、まず元の文章を一文ずつに区切ってください。
句点・？・！のあとで切りますが、かぎ括弧の中の句点では切らず、閉じかぎ括弧を取り残さないようにしてください。
あわせて、段落の切れ目も控えておいてください。
原文の語を修正せずに、文ごとの働きを読むためです。

要件定義書が無ければ、9つの項目を推定して `## <番号>. <項目名>` の見出しで外のファイル `推定要件.md` に記述し、最初の行に「**推定した要件**」と記述して、利用者の明示した要件と混ぜないでください。
設計書は推定しません。
段落が2つ以上ある文章では `check` が設計書の無いことを警告しますが、人の文では問題として扱わないでください。
記録を作成し、`req` で推定した要件定義書を登録してください。

```bash
python3 "<このスキルのフォルダ>/scripts/tsuzuri.py" init human.md
python3 "<このスキルのフォルダ>/scripts/tsuzuri.py" req human.md.tsuzuri --file 推定要件.md
```

一文ずつ、前の文と要件定義書に照らして、まず `memo --inferred` で推測した執筆意図を記録し、続けて `write --human` で文機能を付与してください。
人の文には書き手の執筆意図が無いため、その文が何をしているかを文と前後から推測し、読み取ることができない点は「不明」と記述して、意図を作り込まないでください。
推測した執筆意図には `by: inferred` の印が付いて書き手の意図と分けて記録され、アプリでは「tsuzuri で執筆した文ではないため推測」と添えて表示されます。
ID とバージョンは、省くと自動で付きます。
人の文の箇条書きで1項目に2文以上あるときは、2文目から `--cont` を付けて、前の文と同じ項目に続けてください。

チャット AI が書いた文章を読むときは、[書いた経緯の書き出し](session-log-prompt.md)のプロンプトを、利用者にその会話へ貼ってもらってください。
返ってきた答えの確かさが「会話にある」の文は `memo --reported` で、「推定」の文は `memo --inferred` で執筆意図を残します。

記録を人と共有するときは、`pack` で記録と文書を1つの `.tsz` にまとめ、受け取った人は `unpack` で展開します。

```bash
python3 "<このスキルのフォルダ>/scripts/tsuzuri.py" memo human.md.tsuzuri --inferred --text '<文と前後から推測した執筆意図>'
python3 "<このスキルのフォルダ>/scripts/tsuzuri.py" write human.md.tsuzuri --human --text '<人が書いた一文をそのまま>' --tags '{"relation":"段落の始まり","importance":"核","role":["主張"],"technique":[],"place":"8. 言いたいこと"}'
```

レビューは `SKILL.md` の「1. 書く」と同じく指摘レビューと改善レビューを分けて行いますが、「執筆意図どおりに執筆できたか」は対象外です。
また、推定した要件定義書と異なるだけで誤りだと断定しないでください。

```bash
python3 "<このスキルのフォルダ>/scripts/tsuzuri.py" review human.md.tsuzuri --sid s0001 --ver v001 --aspect '指摘：要件の網羅（place）' --text '<指摘>'
python3 "<このスキルのフォルダ>/scripts/tsuzuri.py" check human.md.tsuzuri
```

人の文では改善の案を自分で反映せず、記録の場所、推定した要件定義書、指摘と改善の案、検査の結果を渡してください。
ただし、利用者自身のドラフトや「評価して直して」と依頼された文章のように、利用者が直す立場にある文章では、反映してよいかを、反映する案の範囲を選択肢にして利用者に確認してください。
他人の記事や公開済みの文章を読むだけの依頼では確認せず、反映を求められたときに[2. 直す](revise.md)で行ってください。
